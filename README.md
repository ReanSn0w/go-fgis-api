# go-fgis-api

Go-клиент для поиска деклараций и сертификатов, получения их публичных карточек и разрешения справочных ID ФГИС Росаккредитации. Зависимостей кроме стандартной библиотеки Go нет.

## Авторизация

Клиент воспроизводит поток, наблюдавшийся в HAR: открывает страницу реестра и получает `session-cookie`, отправляет `POST /login` с cookie и JSON `username/password`, затем забирает Bearer из заголовка `Authorization` ответа. Тот же cookie jar и Bearer используются при запросах к API. Учётные данные и токен хранятся только в памяти клиента.

## Использование

```go
client, err := fgis.New(fgis.Config{
    Username: os.Getenv("FGIS_USERNAME"),
    Password: os.Getenv("FGIS_PASSWORD"),
})
if err != nil {
    return err
}
defer client.Close()

query := fgis.DefaultDeclarationSearchRequest()
query.Page = 0
page, err := client.SearchDeclarations(ctx, query)
if err != nil {
    return err
}
for _, declaration := range page.Items {
    fmt.Println(declaration.DeclarationNumber)
}
```

`SearchDeclarations` авторизуется при первом вызове. Строки ответа описаны типом `Declaration`; общая обёртка списка — `Page[T]`.

Для долгоживущего процесса запустите фоновое обновление:

```go
client, err := fgis.New(fgis.Config{
    CredentialsProvider: func(ctx context.Context) (fgis.Credentials, error) {
        return fgis.Credentials{
            Username: os.Getenv("FGIS_USERNAME"),
            Password: os.Getenv("FGIS_PASSWORD"),
        }, nil
    },
    RefreshBefore: 5 * time.Minute,
})
if err != nil {
    return err
}
if err := client.Start(processCtx); err != nil {
    return err
}
defer client.Close()
```

`Start(ctx) error` получает токен, если нужно, и запускает один фоновый цикл. Уже действующий токен может использоваться без нового входа. Ошибка начального входа возвращается вызывающему коду; цикл при этом не запускается, а `Start` можно повторить. Повторные и одновременные вызовы `Start` при работающем цикле не создают новый цикл и не заменяют его контекст.

Отмена `processCtx` останавливает цикл, сохраняя возможность обычных запросов. Следующий `Start` с новым контекстом дожидается завершения прежнего цикла и запускает новый.

`Close() error` окончательно закрывает клиент: отменяет контекст фонового цикла, включая его текущий HTTP-запрос, и дожидается завершения. Повторный `Close` и закрытие до `Start` допустимы. После закрытия методы авторизации и запросов возвращают `ErrClosed`. Уже начатые пользовательские запросы управляются своими контекстами. Клиент безопасен для одновременных вызовов.

`CredentialsProvider` имеет приоритет над `Username`/`Password` и вызывается при каждом новом входе. Это позволяет получать обновлённые учётные данные из окружения или менеджера секретов. Ошибка провайдера возвращается как ошибка авторизации; перехода к статическим данным нет. Провайдер должен учитывать отмену переданного контекста, чтобы остановка клиента не зависела от зависшего получения секрета.

JWT `exp` определяет момент следующего входа, по умолчанию за пять минут до истечения. Если `exp` нет, обновление происходит через час. После временной ошибки входа цикл повторяет попытку через 30 секунд; ранее полученный токен сохраняется до истечения. Запросы также обновляют токен при необходимости и один раз повторяют запрос после HTTP 401. Для смены пароля в работающем процессе передайте `CredentialsProvider`.

`RefreshBefore: 0` выбирает значение по умолчанию — пять минут; отрицательное значение отклоняется в `New`. Если срок жизни полученного токена короче этого интервала, обновление планируется на половину оставшегося срока.

Ошибки фонового обновления можно получать через `Config.OnRefreshError`. Обработчик вызывается из фонового цикла, поэтому он должен быстро завершаться и не вызывать `Close` синхронно.

## Поиск и карточки

`DefaultDeclarationSearchRequest()` и `DefaultCertificateQuery()` создают наблюдавшиеся пустые запросы первой страницы. Номер `Page` начинается с нуля. `SearchDeclarations` возвращает `Page[Declaration]`, а `SearchCertificateSummaries` — `Page[CertificateSummary]`. У реестров разный JSON поиска по колонке:

```go
declarations := fgis.DefaultDeclarationSearchRequest()
declarations.Filter.AddColumnSearch(fgis.DeclarationColumnSearch{
    Name: "productFullName", Search: "проектор", Type: 0,
})
certificates := fgis.DefaultCertificateQuery()
certificates.Filter.ColumnsSearch = []fgis.CertificateColumnSearch{
    {Column: "productFullName", Search: "проектор"},
}
```

Для типизированного поиска сертификатов подтверждены `Status`, `IDCertType`, `IDCertObjectType`, `IDCertScheme`, диапазоны дат и поиск по колонкам. `CertificateFilter.Extra` принимает дополнительные ключи в виде `json.RawMessage`, если их формат подтверждён вашим запросом; известные ключи он не заменяет. Исходный `SearchCertificates(ctx, CertificateSearchRequest)` с расширяемым `map[string]any` и сырыми строками `Certificate` сохранён для совместимости. Для отдельного клиента сертификатов можно указать `StartPath: "/rss/certificate"`.

Числовой `ID` строки списка передаётся в `GetDeclaration(ctx, id)` или `GetCertificate(ctx, id)`. Методы возвращают отдельные типы карточек `DeclarationDetails` и `CertificateDetails`: продукцию и её `Identifications`, лаборатории с `Protocols`, документы, историю статусов и связи замены. Массивы сохраняют порядок и повторы. Nullable-поля представлены указателями или `json.RawMessage`; поле `Raw` содержит исходный JSON карточки для ещё не описанных ключей. Даты и время остаются строками в формате сервера. Связанные карточки не загружаются автоматически.

`GetDeclarationIdentifiers` и `GetCertificateIdentifiers` возвращают именованные значения реестров. Их схемы различаются, а ID страны в `OKSM` — строка. `GetNSIMulti(ctx, NSIQuery)` выполняет пакетный запрос `/nsi/api/multi`; известные группы имеют типизированные поля, все группы доступны также в `NSIResponse.Groups` как сырой JSON. В карточке `IDTnveds` и `IDOkpds` — внутренние ID записей справочника, а не коды классификатора. Для получения кодов и названий вызовите `ResolveProductCodes(ctx, tnvedIDs, okpdIDs)`. Результат сохраняет порядок и повторы входных ID; если запись не найдена, `Code` и `Name` равны `nil`. Сертификатные `IDOkpds` в исследованной выборке были только пустыми, поэтому их элементы пока `json.RawMessage`.

Полный компилируемый сценарий поиска продукции, открытия карточки и разрешения кодов есть в [example_test.go](example_test.go).

## Границы наблюдений

- Модели основаны на ограниченной выборке публичных запросов от 06.10.2026, а не на опубликованной спецификации API. [Описание наблюдений](docs/registry-observations.md) и [обезличенные схемы](plans/evidence/registry-api-2026-10-06.json) фиксируют подтверждённые маршруты и поля. Неизвестные ключи списков доступны через прежний сырой поиск сертификатов, а карточек — через `Raw`.
- Формат непустой границы даты не подтверждён: выбранная в интерфейсе дата не появилась в записанном запросе. У деклараций пустые границы — строки `""` в `minDate/maxDate`, у сертификатов — `null` в `startDate/endDate`. Перед применением непустой даты проверьте её JSON в актуальном браузерном запросе.
- Значения `size` и `total` в ответах отличались от длины `items`; смысл счётчиков сервером не документирован. В запросах деклараций наблюдались `count: 0` и `count: 1000`, в типизированном запросе сертификатов `count` нет. Библиотека возвращает эти значения без интерпретации и не обещает выгрузку всего реестра.
- Фильтры сертификатов по происхождению, группам продукции, перечням, регламенту и виду заявителя не подтверждены. Для них предусмотрен `CertificateFilter.Extra` без догадок о типах.
- Поля карточек, наблюдавшиеся только как `null` или пустой массив, имеют `json.RawMessage` или `[]json.RawMessage`; конкретный тип для непустого значения ещё не подтверждён. Генератор типизированных карточек расположен в [scripts/generate_details.py](scripts/generate_details.py).
- `exp` декодируется только для планирования обновления; криптографическая подпись JWT не проверяется клиентом. Ошибки HTTP содержат метод, путь и статус, но не тело ответа, где могут быть персональные данные.

## Тесты

```sh
go test ./...
```

Обычный запуск использует HTTP-ответы в памяти и не обращается к ФГИС. GitHub Actions выполняет именно его и явно задаёт `FGIS_LIVE_TEST=0`.

Для проверки конкурентных вызовов:

```sh
FGIS_LIVE_TEST=0 go test -race -count=1 ./...
go vet ./...
```

Тесты проверяют авторизацию, жизненный цикл, ошибки обновления, ограниченный повтор после HTTP 401, маршруты и JSON новых запросов. Фикстуры списков, карточек и справочников обезличены, но сохраняют наблюдавшиеся ключи, типы и вложенность. Примеры публичного API в `example_test.go` компилируются, но не выполняются при обычном запуске тестов.

Отдельный тест настоящего API запускается только по запросу. Задайте `FGIS_USERNAME` и `FGIS_PASSWORD` через окружение или менеджер секретов, затем выполните:

```sh
FGIS_LIVE_TEST=1 go test -run '^TestLiveDeclarationsAPI$' -count=1 -v ./...
```

Тест открывает страницу деклараций, проходит `/login` и проверяет, что API вернул хотя бы одну запись. Учётные данные не зашиты в код и не используются в CI.
