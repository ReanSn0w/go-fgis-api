## Что мы делаем?

Расширяем `go-fgis-api` на основании запросов, записанных в Chrome DevTools 06.10.2026: добавляем типизированный поиск сертификатов, недостающие поля деклараций, полные карточки обоих реестров и получение справочных значений. Сохраняем совместимость существующих экспортируемых методов и типов. Интеграция с ассистентом сертификации, скачивание файлов и операции изменения реестра в этот план не входят.

Исследование выполнено через интерфейс сайта и Network. Сохранены [схемы ответов, примеры запросов и сопоставление с библиотекой](../evidence/registry-api-2026-10-06.json). В этом файле нет HTTP-заголовков, токенов и значений из карточек организаций или физических лиц. Схемы описывают наблюдавшуюся выборку, а не гарантированный контракт сервера.

Выборка: три ответа списков деклараций, пять ответов списков сертификатов, две карточки деклараций и три карточки сертификатов. Число строк учитывает повторения между поисками. Карточки: [декларация 21991975](https://pub.fsa.gov.ru/rds/declaration/view/21991975/common), [декларация 21990170](https://pub.fsa.gov.ru/rds/declaration/view/21990170/common), [сертификат 3738777](https://pub.fsa.gov.ru/rss/certificate/view/3738777/baseInfo), [сертификат 3738769](https://pub.fsa.gov.ru/rss/certificate/view/3738769/baseInfo), [заменивший его сертификат 3738792](https://pub.fsa.gov.ru/rss/certificate/view/3738792/baseInfo).

Подтверждены следующие маршруты:

| Метод | Путь | Назначение |
| --- | --- | --- |
| POST | `/api/v1/rds/common/declarations/get` | Список деклараций |
| POST | `/api/v1/rss/common/certificates/get` | Список сертификатов |
| GET | `/api/v1/rds/common/declarations/{id}` | Полная карточка декларации |
| GET | `/api/v1/rss/common/certificates/{id}` | Полная карточка сертификата |
| GET | `/api/v1/rds/common/identifiers` | Именованные справочные значения деклараций |
| GET | `/api/v1/rss/common/identifiers` | Именованные справочные значения сертификатов |
| POST | `/nsi/api/multi` | Пакетное получение записей справочников по ID |
| POST | `/nsi/api/oksm/get` | Записи классификатора стран |
| POST | `/nsi/api/status/get` | Записи справочника статусов |

## Для чего мы делаем?

Существующие `models.go` и `registry.go` покрывают только списки. В `Declaration` описаны 59 из 60 полей, найденных в объединённой выборке: отсутствует `declReplacedNumber`, встретившееся лишь в одной из 30 строк. Сертификат пока представлен `map[string]json.RawMessage`; теперь подтверждены 37 полей его строки. Карточки содержат значительно больше информации: продукцию, организации, лаборатории, протоколы, документы, стандарты, статусную историю и связи замены.

Существенные различия, которые реализация должна сохранить:

- Декларации используют `columnsSearch: [{"name":"productFullName","search":"проектор","type":0}]`; сертификаты — `[{"column":"productFullName","search":"проектор"}]`. Для сертификатов подтверждено сочетание `manufacterName` и `productFullName` в одном запросе. Написание `manufacter` принадлежит API.
- У деклараций пустой диапазон дат — `minDate/maxDate` со строками `""`. У сертификатов — `startDate/endDate` со значениями `null`. Непустую границу даты пока подтвердить не удалось: выбранная в интерфейсе дата не попала в экспортированный запрос. Формат отправки непустых дат остаётся открытым вопросом.
- Пустой запрос сертификатов содержит `idCertScheme: []`, оба диапазона дат и `columnsSearch: []`; другие незаданные фильтры опущены. После выбора действующего статуса добавляется `status: [6]`. Поля `count` в запросах сертификатов нет; сортировка — `date DESC`. Декларации используют `count: 0`, затем в исследованной последовательности `count: 1000`, и `declDate DESC`.
- `page` начинается с нуля в обоих реестрах. При запросе 10 строк ответное `size` совпадало с `total`, а не с длиной `items`. Для деклараций оба значения в выборке равны 1000; это не доказывает полноту найденных результатов.
- В карточках `product.identifications[]` содержит внутренние `idTnveds[]` и `idOkpds[]`. Коды и названия разрешаются запросом `/nsi/api/multi`. ID справочной записи нельзя выдавать за код ТН ВЭД или ОКПД2.
- Подтверждены несколько идентификаций продукции, несколько лабораторий, вложенные протоколы и стандарты. Для сертификата 3738777 — две лаборатории и восемь стандартов одной идентификации. Переходы между продукцией, лабораториями и историей статусов этой карточки не вызвали дополнительных запросов данных.
- В карточках сертификатов `replacement` и `replacedBy` — nullable-объекты с `certSource`, `certTarget`, `replacementReasonIdList`. При открытии прекращённого сертификата сайт дополнительно загрузил заменившую его карточку.
- `annexes[].ord` у декларации пришёл строкой, у сертификатов — числом. Даты карточки представлены строками `YYYY-MM-DD`, а временные отметки — строками с дробными секундами без часового пояса. `time.Time` без специальной обработки этим форматам не соответствует.
- Справочники `identifiers` различаются: например, `notActive` у деклараций и `notactive` у сертификатов; ID стран — строки. Не все справочные объекты имеют одинаковый набор полей.
